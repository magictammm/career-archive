# 04 · 归档与同步

## 本地目录骨架

```
<档案根>/
├── 00_总览                 overview.md（这段经历的全局摘要）
├── 09_原始底稿             K1-1 时间线、手写稿扫描、早期草稿
├── 项目深挖/               每个项目一份三段式 md
├── 20_能力图谱/            能力矩阵、雷达图
├── 30_职业曲线/            薪酬阶梯、职级变化
├── 40_派生输出/
│   ├── 简历/               主简历 + 各岗位定制版 + 框架页 html
│   ├── 述职晋升/
│   ├── STAR故事库/
│   └── 面试问答/
├── 99_证据登记/            原始文档摘录、出处索引
└── archive.config.json     框架页数据配置
```

规则：
- 编号前缀固定，新增分类用两位数字续编，不要重排已有编号（外部链接会失效）。
- 「项目深挖」是唯一放三段式 md 的地方，命名 `项目深挖-NN_项目名.md`。
- 派生输出只读上游，不反向修改深挖文档。

## 项目资产库（网盘 / tdrive）

与本地结构一一对应，用目录 ID 而非路径定位。上传要点：

1. `file_upload` 申请地址 → `curl -T` PUT → **必须**再调 `file_upload_complete` 才真正落库。PUT 返回 200 ≠ 成功。
2. PUT 必须带全签名头：`Authorization` / `Cache-Control` / `Content-Type` / `x-cos-acl` / `x-cos-crc32c-flag` / `x-cos-security-token` / `x-cos-storage-class`。**漏 `x-cos-storage-class` 直接 403**。
3. `file_upload_complete` 有约 5 秒频控（错误码 406450），批量上传必须**串行 + 间隔 ≥6 秒**，并发必失败。
4. 往已删除的目录上传报 `323908` 或 `12002`，先 `dir_list` 确认目录还在。
5. 上传后回查 `dir_list` 的 `total_num`，与本地产出数量对账后再向用户汇报。

## 知识库同步（ima 为例）

```
<知识库>/
├── N、<某段经历>/
│   ├── 01 公司A/
│   ├── 02 公司B/
│   └── ...
```

上传链路（缺一步就失败）：

```
preflight-check  →  check_repeated_names  →  create_media  →  COS 上传  →  add_knowledge
```

- `title` 必须原样等于文件名（含扩展名），不改名。
- 重名时只能「保留两者（追加时间戳）」或取消，**不支持覆盖**——所以要迭代版本时，本地先用新文件名。
- 上传前逐级 `get_knowledge_list` 确认目标文件夹存在，记下 `folder_id`。

### 已知限制（踩过的）

| 事项 | 结论 |
| - | - |
| 删除知识库条目 | **开放接口不支持**，`delete_knowledge` / `delete_folder` 全 404，只能让用户在客户端手动删 |
| 移动条目 | `move_knowledge` 返回 code=0 但 `move_results` 为空、实际不移动。不可用 |
| 新建文件夹 | `create_folder` 可用，但会忽略 `parent_folder_id`，一律建在知识库根 |
| 列表字段 | `get_knowledge_list` 的数据在 `data.knowledge_list`；`search_knowledge_base` 在 `data.info_list` |

因此：**上传前把目录结构和文件名定好**，因为事后改不了。宁可在本地多迭代几次，也不要传错再想挪。

## 证据登记

每个结论都要能回溯。登记表三列：结论 / 出处 / 类型。

| 类型 | 含义 |
| - | - |
| 已核 | 原始文档有明确出处，可贴原文关键句 |
| 口述 | 用户本人确认，无文档支撑 |
| 待确认 | 尚无任何来源，写在待确认清单里 |

用途：
- 简历里只写「已核」与「口述」支撑的内容。
- 面试被追问细节时，能立刻翻到出处。
- 文档与口述冲突时，在证据表里并列记两条，注明「以用户为准」。

## 记忆落盘

档案类工作周期长、跨会话，必须留两处笔记：

1. **长期记忆**（项目级）：时间线基线、产品台账、口径冲突裁决结论、冻结版约定、目录 ID。控制在精简范围，超限会被截断。
2. **当日日志**：本日产出、待确认项、踩坑与修法。只记有长期价值的，不记临时路径和报错原文。

长期记忆写法：**结论 + 出处 + 日期**。例如「4902 芯片＝hi3519AV200（用户 2026-10-12 更正，与飞书原文 AV00 冲突，以用户为准）」，后续任何会话都能直接引用，不必重查。
