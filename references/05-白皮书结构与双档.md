# 05 · 白皮书结构与双档

> 白皮书 = 一本可翻页的单文件 HTML，把「时间线 → 逐段经历 → 项目深挖 → 曲线与薪资 → 能力与路径」串成一份底档。
> 它比简历长，但结构固定；固定了才能横向对比、才能反复复用。

---

## 一、章节结构（可配置，但顺序不要乱）

| # | 章节 | 必备 | 数据来源 | 说明 |
| - | - | - | - | - |
| 0 | 封面 | ✓ | — | 标题 / 姓名 · 岗位标签 / 版本号 + 日期 / 内外档说明 |
| 1 | 目录 · 总览 | ✓ | 阶段 2 时间线 | 目录 + 竖排时间线，一眼看完全部经历 |
| 2 | 职业框架定位 | ✓ | 阶段 2/3 | 主线叙事（一句话串起整条路径）、职业标签、当前定位 |
| 3 | 学业与教育 | 可选 | L1/L2 | 只在「学历是加分项」或「跨专业转行需要解释」时单列 |
| 4 | 早期 / 空档 / 非正式经历 | ✓ | 阶段 2 | 兼职、Gap、个人项目：**显式列出，不藏**，标注性质 |
| 5…N | 每段正式经历一章 | ✓ | 阶段 3 + 4 | 见下方「经历章内部结构」 |
| N+1 | 职业发展曲线与薪资 | ✓ | 阶段 2 + 3 | 五维走势（职级/职责范围/业务复杂度/团队规模/影响力）+ 薪资阶梯 |
| N+2 | 能力模型 | ✓ | 阶段 4 汇总 | 能力项 → 对应项目证据（每条能力至少 1 个项目锚点） |
| N+3 | 性格 / 工作风格 | 可选 | 测评 / 用户口述 | 有测评就放，没有就别硬编 |
| N+4 | 职业路径规划 | ✓ | 用户目标 | 1–3 年目标、差距、动作、风险 |
| 末 | 全书完 | ✓ | — | 版本号 + 日期 + 更新说明 |

**经历章内部结构（每段经历都一样）**：

```
章标题：公司（起止）· 业务定位
  ├ 头部：岗位 / 周期 / 汇报关系 / 一句话主线
  ├ ① 项目甘特图（可点 → 打开该项目深挖文档）
  ├ ② 项目一览表（周期 / 项目 / 平台或形态 / 我的角色 / 阶段与结果）
  ├ ③ 分阶段深度复盘（按年或按 PI 分段，STAR 口吻）
  └ ④ 口径提醒（哪个说法对外要收着讲、哪个数字不能吹）
```

> 项目数超过 8 个时，甘特拆两张：**主业务线** + **支撑/平台线**（例：整机与硬件 / 软件与平台）。两图年份列必须对齐。

## 二、技术规范（单文件 HTML）

- **一个文件**：CSS / JS / 文档数据全部内联，双击可开、离线可用、可直接发人。
- **翻页**：`.page` 容器 + `go(n)` + 方向键 + 侧边栏，一次只显示一页；页面内滚动。
- **文档弹层**：所有项目 deepdive md 存进 `<script id="docdata" type="application/json">`，键与条目 `data-key` 一一对应；点条目 → 弹层渲染 md。
  - 渲染器只需支持：标题、段落、无序/有序列表、表格、引用块、代码块、分隔线、粗体、行内代码、链接。
  - 事件用**事件委托**绑在 document 上（`closest('[data-key]')`），不要逐条 addEventListener —— 条目是动态渲染的，逐条绑必然丢失。
  - 无文档的条目标不可点或提示「暂无文档」，**不留点击落空**。
- **检索一致性**：交付前必须跑一次「键覆盖校验」——所有 `data-key` / `openDoc('X')` 引用都要在 docdata 里有对应文档，反向也不能有孤儿文档。
- **打印**：`@media print` 下隐藏侧边栏、弹层、切换胶囊，页面全部展开（白皮书要能导出 PDF 交人）。

### 双档机制（内部 / 对外）

一份文件两套口径，靠 CSS 类切换，**不用维护两份文档**：

```css
body:not(.public) .only-ext { display: none !important; }   /* 默认内部档 */
body.public .only-int      { display: none !important; }   /* 对外档 */
```

- 切换按钮固定在右上（`内部档 / 对外档`），选择写进 localStorage，刷新后保持。
- **必须双档的内容**：薪资、离职原因、外包/派遣等雇佣细节、未公开的经营数据、负面复盘。
- **对外档写什么**：只写雇主主体与业务结果；口径统一、不出现「外包 / 派遣 / 派驻」字样。
- 交付时明确告知用户：**默认档是哪一个**，对外分享前要切。

## 三、口径规则（踩过坑，照抄）

| 场景 | 规则 |
| - | - |
| 雇主主体 | 对外统一写**甲方公司全称**；内部档另存一行真实签约主体（供应商 / 派驻方） |
| 外包 / 派遣 | 对外不出现「外包」二字；岗位性质对外写「全职」，内部写真实性质 |
| 公司缩写 | 首次出现写全称，后文可简称；**标题、目录、封面一律全称**，缩写只留在正文与技术名词里 |
| 时间口径 | 「我参与的区间」≠「项目立项到上市」；甘特条长度按参与区间，图例写明 |
| 薪资 | 只进内部档；写月薪 + 变动百分比；**每次改动都要重算整条涨幅链** |
| 职级 | 内部写真实职级，对外写岗位名（如「专员级 BA」对外只写 Business Analyst） |
| 不确定项 | 写进「待确认清单」，正文用 `待补` 占位，**不猜数字** |

**薪资链自洽公式**（改一个数就要全链重算）：

```
变动% = (本期月薪 − 上期月薪) / 上期月薪 × 100，四舍五入到整数
校验：链上每一段的 +x% 都能用相邻两期算出来；插入新数据后，后续所有变动百分比都要重算
```

## 四、验收清单（交付前逐条过）

- [ ] `data-key` ↔ docdata 键：双向零缺失、零孤儿
- [ ] 双档切换后，对外档不含薪资 / 外包 / 负面复盘字样
- [ ] 用无头浏览器实际截图：封面、任一经历章、薪资页、任一弹层
- [ ] 搜索结果：全文搜索「外包 / 缩写 / 旧公司名 / 旧薪资」无残留
- [ ] 版本号、日期、页数三处一致
- [ ] 文件大小合理（单文件通常 200–600 KB），无外链依赖（`<link>` / `<img src="http">` 均为 0）

> 截图自检比肉眼读 CSS 可靠：起一个 headless Chrome，注入 `openDoc('某键')` 后截图，看弹层是否真的出来。
> 高频坑：CSS 里残留 `display:none !important` 会把弹层永久隐藏，而页面看起来完全正常。
