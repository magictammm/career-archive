# 01 · 信源与时间线

## 信源分层与裁决顺序

| 层级 | 典型信源 | 能回答什么 | 不能回答什么 |
| - | - | - | - |
| L1 用户确认 | 口述、手写稿、逐条选中 | 真实起止、真实岗位、真实薪酬、内部决策动因 | 精确数字（易记混） |
| L2 公司文档 | 立项书、PRD、周月报、季度/年度总结、会议纪要、评审记录 | 项目规格、阶段节点、量化结果、组织分工 | 个人贡献的归因 |
| L3 旧简历 | 各版本 CV、投递记录 | 表达方式、对外口径 | 时间与职级（普遍美化） |
| L4 公开渠道 | 官网、电商详情页、行业报告、媒体报道 | 市场容量、竞品、价格带 | 个人角色 |

裁决规则：

1. **时间 / 岗位 / 薪酬**：L1 > L2 > L3。用户改口时以最后一次为准，并把改口记进记忆。
2. **项目规格 / 数据 / 节点**：L2 > L1（用户记不清细节时用文档），但文档与用户口述冲突时——**以用户为准并在文档里注明差异**。
3. **市场与竞品**：L4 补充即可，不要拿公开数据反驳用户的一线判断。
4. **个人贡献**：只有 L1 能定。文档里的「XX 负责」不等于本人主责。

## 时间线冲突的四种裁决手法

- **末次出现法**：某项目在某季度总结里最后一次出现，基本等于实际结束月。逐份文档比对，不要看单份。
- **首次出现法**：立项书日期 ≠ 我参与日期。找「我加入后第一份提到该项目的周报」。
- **并行判定**：两个阶段时间重叠不代表记录错误，可能是同期双线决策（一条交付线、一条方向线）。先问，别急着改成一个接一个。
- **排期终点 ≠ 离职时点**：项目排期写到离职后几个月是正常的，注明「规划终点」与「我离职时进度」两件事。

## 薪酬阶梯

- 必做：入职 → 每次调薪 → 离职，逐档记录；算总涨幅与年化。
- 标出跳涨点（哪次跳槽/晋升带来最大涨幅），这是职业曲线叙事的核心。
- 与岗位变更对齐：涨薪往往伴随职责范围变化（带人、跨线、独立负责产品线），写进时间线备注。

## 时间线表标准格式

| 阶段 | 真实 | 简历口径 |
| - | - | - |
| 学校 / 公司 + 岗位 | 实际起止 + 实际职级 + 薪酬 | 对外写法 |

要求：

- Gap、兼职、外包、试用期全部单列，不合并进「连续工作」。
- 简历口径栏只写「对外怎么写」，不写理由。
- 表下补三条：薪酬阶梯、跳涨点、副业/并行收入（如用户愿意提供）。

## 常见坑

- **拿简历口径当真实**：简历里的入职时间常比实际早 3–6 个月，职级常上修一级。必须先问一遍真实值。
- **用入职时间反推参与项目**：试用期也可能已经在主责项目上，别想当然。
- **把「我参与」写成「项目周期」**：两者常常差半年以上，台账里要分两列。
- **跨地区表述**：涉及港澳台一律写「中国香港 / 中国台湾 / 中国澳门」。
